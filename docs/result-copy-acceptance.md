# 结果文案验收标准

更新：2026-10-21。最新要求：在上一版基础上压缩中间正文约 20%，保留多维度内容与已确认的结语；多结合几个维度，措辞更有余地，语气更亲切；句子完整，表意明确；整体采用总—分—总，结尾结合特点表达对爱与幸福的祝愿，口语更自然，可以俏皮，感情更直接。保留日常语言；四档改用用户确认的文字标签。

本标准优先于 2026-10-17 两份调查／方案中的旧文风、字数与命名建议。适用于用户可见的结果文字；内部研究和算法说明另行保留。

## 1. 验收目标

用户扫一眼就能知道：受骗倾向处于哪档、自己有什么特点。

内容正确、选择规则正确、语言易懂、表达简短，四项都通过才可交付。不能用“有依据”替代语言验收。

## 2. 长度与结构

| 项目 | 通过标准 |
| --- | --- |
| 程度标识 | 不容易被骗／可能被骗／容易被骗／超容易被骗 |
| 开头总述 | 一两句，直接说明受骗倾向并概括主要特点；与结果证据一致 |
| 类型名 | 最多 8 个汉字；无需解释就能理解；不能只把程度词加上“型” |
| 中间分述 | 通常约 130—190 个汉字，一至两段；逐句表达不同倾向与具体反应，保留情绪色彩，语气比结语更客观 |
| 结尾总述 | 优先一句完整连贯的话，通常约 30—65 个汉字；温暖而有感情，弱化具体情节与互动，少用并列短句 |
| 单句 | 说完整一件事，交代清楚对象、动作和必要条件；不为缩短句子切碎语意 |
| 主要内容总量 | 通常约 210—290 字；优先检查完整结构、连贯性和可读性，不机械卡字数 |
| 共用说明 | 最多一句、25 个汉字；不在各段重复 |

计数按汉字，不含标点、空格与数字。字数通过后仍须人工检查含义与阅读节奏。与上一版相比，中间正文减少约 20%；不通过删掉独立含义或切碎句子压缩。结语保持已确认风格。

每句只讲一个主要意思。正文优先结合四至六个有依据的维度，合并为三至五个主题。保留特点之间的联系，不写成逐项清单。缺少足够信息时允许较短，不为扩写编造特点。

### 中间正文的逐句检查

- 每句能指出一项倾向，以及它怎样影响信任、期待、付出或选择；纯过渡句、重复赞许和空泛总结删去。
- 相邻句必须增加不同信息。区分“被什么打动”“怎样核对事实”“能否拒绝”“能否停止投入”等测量位置，不把同一个弱点换词说三次。
- 用心动、珍贵、心软、舍不得、踏实等有感受的词贴近真实心理；词语必须服务于该句判断，不堆情绪形容词。
- 以描述为主，保留适当限定，不在中间段落插入祝福、劝导、反问或行动清单。
- 少用“但、也、所以、因此、即使、同时”串起短句。依靠意思本身的顺序形成连贯，必要的转折仍可使用。
- 不在段末用一句话重复已经解释过的反差；总结任务交给开头总述，中间保留不同维度的信息。
- 无突出维度的结果属于例外，只说明结果能支持到哪一步，不为满足“每句有倾向”而编造人格。


## 3. 一眼看懂

- 使用日常词，直接写人的反应或行为。
- 主体和动作要明确；条件、转折和结果应有清楚联系，不能只靠一串逗号让读者自行拼出意思。
- 遵循自然的中文语序：先交代必要的条件或已知情况，再说人的反应；不机械套“某种感受使你产生某种变化”的句型。
- 优先用“你会看对方有没有做到”这类动词表达，减少“行为是否改变没有得到关注”等抽象、被动的说法。
- 不在主语和谓语之间塞很长的修饰；少用多层“的”和生硬的“作出调整、落实决定、关系程度”等名词化表达。完整意思需要较长句子时，按中文阅读节奏组织，不切成碎句。
- 去掉双重否定与模糊指代，例如把“你未必没有察觉”改成“你较能察觉对方在施压”。
- 不用“留出余地、听见感受、让感受跟上决定”等抽象表达代替具体行为。需要时直接说清是否答应、拒绝、继续付出或离开。
- 像温和地与读者交谈，少用分析报告式的评语；让读者感到被理解，而不是被打分或训话。
- 亲切不等于刻意夸奖。不强加“太善良、太重感情”等原因，不用“宝贝、抱抱”等未经选择的亲昵称呼。
- 提醒用“你可以、如果愿意”等邀请语气；不催促读者作出关系决定，也不在每段末尾堆建议。
- 用户可见文字不使用“易感、风险信号、机制、校准、心理分化、结构证据”等术语。
- 不写“本次作答呈现出……”“下面会进一步说明……”等引导句。
- 不用多个形容词堆出人物感，不用比喻替代明确含义。
- 读者不看题目、算法和解释词典，也应读懂每句在说什么。

| 不通过 | 修改方向 |
| --- | --- |
| 你具有较高的自我校准能力。 | 有新的信息时，你愿意回头重新检查自己的判断。 |
| 你存在行动失守的风险信号。 | 你能看出问题，却不太容易拒绝。 |
| 你具有关系价值放大特性。 | 你容易被认可和特别对待打动。 |

右列仅示范语言；实际使用仍须对应结果证据。

## 4. 程度表达

按用户最新确认，四档直接使用以下文案，替代原来的编号和方向说明：

| Stage | 分数后的标识 |
| --- | --- |
| 1 | 不容易被骗 |
| 2 | 可能被骗 |
| 3 | 容易被骗 |
| 4 | 超容易被骗 |

分界仍为 30／50／70，算法与计分不变。页面不再展示“档位越高，受骗倾向越强”。这些标签是程度表达，不作为性格类型或受骗概率。

保留分数与总述、特点分述、祝愿。类型名称仍单独审阅。

不写受骗概率、百分位或“不会被骗”“一定被骗”。边界附近不能因换档就变成另一种人格。

## 5. 准确与自然

- 每个特点有对应字段；不能从 Stage 推断具体行为。
- 有明显保护特点时可写，但不为了安慰强加优点。
- 同分不同特点，正文应有实际差异。
- 允许“容易心动，但能拒绝”等有证据的组合。
- 无突出维度时不硬凑人物特点。
- 祝愿应回应已选特点，让不同结果拥有不同的结尾；不能为写祝福另编一项性格。
- 用户所说的“情景感”是整段的情绪氛围。粉红色让人感到甜蜜可爱，紫色让人感到浪漫深情，橙色让人感到温暖安心。
- 每段只选一种主要底色，让两句话共同表达同一份感情。检查的是读者感受到什么，不是出现了几个甜美形容词。
- 取消“必须有具体场景”的旧要求；不靠晚饭、街角、路灯等道具来证明有情绪。
- 结语前后必须有情感上的联系，不拼接几句通用祝词，也不在结尾突然切回分析或说教。
- 文风基准是用户确认的句子：“希望你认真给出的喜欢能得到温柔的回应，让你慢慢相信，自己也可以被好好爱着。”
- 禁用“既有……又有……”句式，少用同义并列短句。采用有内在联系的递进表达，不通过增加停顿制造温柔。
- 避免将“不愿意、拒绝、犹豫”等表现评价成可爱，不用俏皮话打趣用户的困难。
- 结语整体风格已经确认；其他具体结语仍须按各自特点核对，当前授权已包含文字引用机制与结果页接入；真实浏览器呈现验收仍单独记录。
- 保留轻松的期待与直接的欣赏，明显减弱互动感。不用问句、邀约、假想对话或“说好了”等约定句，不堆叠语气词。
- 不刻意卖萌，不用密集感叹号，不调侃用户的弱点，也不让文本假装与读者已经建立亲密关系。
- 祝愿不能保证未来，也不暗示只有某种性格才值得被爱。
- 不诊断，不推断童年，不断言伴侣正在欺骗。
- 允许“可能、通常、更容易、在某些相处中”等留有余地的表达；避免把每项倾向写成必然发生。
- 模糊的是程度和具体情境，句子含义仍要清楚；不能靠无依据的两面话适配所有人。
- 保留至少两处能区分不同结果的具体特点，不能只写“有时理性，有时感性”。

## 6. 交付检查

1. 检查篇幅、术语、重复和连贯性；不能把单句易懂等同于整段必须很短。
2. 四档文案与算法一致；开头总结不夸大，不生成新的含混程度标签。
3. 检查正文是否有总述、分述、祝愿三个完整部分；结尾是否回应具体特点。
4. 检查两组临界分数：只改变程度，不改变无依据的人物判断。
5. 对照结果字段，逐句核对特点。
6. 把文字单独展示，请读者复述“结论”和“特点”；不能仅问“好不好看”。

真人试读前只能标为“已完成内部检查”。真实页面的一眼可读性与用户审美确认，不能用字数统计代替。
