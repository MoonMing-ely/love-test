# V1.5：有边界的连续计分调整

日期：2026-10-20。用户授权先修改、模拟，再检查用户可感的分差、奇怪跳变、方向和复杂度。当前已写入本地工作区；未提交、发布或部署。经历适用性明确不在本轮范围。

## 目标与边界

保持六层结构、85题题库、28题流程、抽题V4、答案快照、缺失规则和15～85显示标尺。阶段仍按30/50/70划分，本轮不靠重新划档改善切换统计。前一至三层和抽题器未修改。

修改集中于第四层证据映射、第五层机制及第六层合成。结果页只同步新的诊断字段和版本；未实施现有未跟踪的结果文案方案。没有按题号、画像、答题顺序、旧分数或目标档位做修分。

本轮工程验收：单维输入增加0.01时分数变化不超过1.1；风险特征增强不得降分，保护能力增强不得加分；小幅单题变化（涉及的每个原始维度变化均≤1）最大分差≤12且不得跨两档；已知B03相近选项反例差值<10。它们是用于排除明显违和的工程边界，不是真人心理测量标准。

## 统一表达式

第四层仍统一提供High/Low字段，但改为全区间线性证据：

```text
High(x) = x
Low(x) = 1 - x
```

输入仍在0～1范围校验；null仍是缺失。移除0.2/0.8提前饱和，避免对中间差异先放大1/0.6，又使两端差异消失。这里的High/Low是工程证据强度，不是概率或经真人标定的隶属度。

第五层：P1保留最高两项80%/20%；P2仍保留关系通道与三项独立证据取最大值，但关系通道只由H支持，J_hole只解释短板、不再推高风险。P3以Low(B)为核心，保留原E支持，不再要求High(J)才能启动。P4保留短板，但更重视实际停止：

```text
P3core = Low(B)
P3 = core * [1 + 0.2 * (1-core) * High(E)]

t = Low(T), f = Low(F)
P4core = 0.5*max(t,f) + 0.3*t + 0.2*min(t,f)
P4 = core * [1 + 0.15 * (1-core) * High(E)]
```

当止损更弱时，P4核心为0.8t+0.2f；分化更弱时为0.5t+0.5f；在t=f处连续。它不把心理纠缠等同于实际无法停止，仍保留二者贡献。

第六层替换旧激活、锚点深度、均值兜底与额外共现曲线，只有一条整合公式：

```text
severity = [30*P1, 62*P2, 70*P3, 75*P4]
strongest = max(severity)
supplement = 0.1 * (sum(severity) - strongest)
R0 = strongest + supplement
R = R0 - 8*M*min(1, R0/40)
S = linear_interpolation(R, [0,30,70,91.2] -> [15,30,70,85])
```

62/70/75延续原行为路径充分激活时的严重度上限；单独P1由50降至30，情感敏感仍独立贡献，也仍支持其他风险。上限91.2由75+0.1*(30+62+70)推导，避免偷偷裁剪。M原抵减形式不变。

各次要路径对R0都有10%的连续贡献，不再被max完全盖住。公式是0.9×max+0.1×sum，因此单调连续；max/min交接可以有斜率折点，不宣称处处可微。最终分段插值也连续，斜率≤1。M的抵减使R对R0的斜率为1−0.2M或1，始终为正。

第五层各风险证据对保护维度单调不增，E/H增强单调不减；P2去除J_hole支持后不再有判断增强却加分的例外；P3去除High(J)门控后不再产生P2/P3交接低谷。不存在根据上次分数限制变化的有状态规则。

Path按实际严重度排序，解释权重仍不用于总分。Shape改为“整体较低／单项突出／多项中等／多项突出”，描述机制形状，不再与总分档位争夺“高风险”的含义。标签阈值、排序和入选仍可离散改变，但不进入计分。

## 连续性、结构与兼容

- 正式16个Node测试文件通过；包含1000组全链路、10000组第六层检查、12000次单维方向检查、4096种极端输入及49152次极端点邻域检查。
- 另一组12000次维度方向审计：原版390次反向，当前0次；本组单维增加0.01的最大影响0.709分，增加1e-8最大影响约7.10e-7分。数学方向论证如上，模拟不是对全部实数输入的穷举。
- 检查计分主体交接、P4短板交接、标尺折点、Path/Shape阈值；解释阈值改变不改变总分。
- 删除了旧激活、深度、共现曲线及未被消费的权重配置，没有在运行时保留双算法或逐题修分。旧版仅作为离线对照读取。
- 参数/第六层1.5、第四层1.3、第五层1.2、第三层1.1；信封V3与抽题V4不变。答题和结果全部计分资源统一更新为20261020-runtime-v15-v4-1。
- 旧V1.4结果提示重测，不自动重解释；有效未完成答题保留，结束时使用新版。离线DOM检查覆盖28题完成、结果刷新数据、六层显示、版本隔离、无效结果和存储失败。

当前环境没有可用浏览器连接，未做真实浏览器点击或视觉验收；DOM测试不等同于浏览器端到端验收。

## 剩余问题与停止边界

小幅作答变化明显改善，但强烈相反的行为选项仍能差约24分；只更换题组的最极端同人差仍达22.41分。这些仍属于用户可感的问题，不能宣称全面解决。本轮不继续修改题库、题量或堆叠封顶补丁；后续需单独复核题目证据集中度和题组内容可比性。

30/50/70附近的硬分档仍会因很小分差换档。连续分数与具体特点不因此突变；若产品后续要呈现临界状态，应另行设计，不从本轮模拟推断置信区间。

真实效度、真实重复作答稳定性和用户对新分数的理解均未验证。经历适用性按用户要求未处理。

## 复现

准备基线（只读Git导出，无需运行外部服务）：

```sh
mkdir -p /tmp/love-v14-baseline
git archive e1018c4a2eb26b4dae29256f03a0b032a63a7bc1 js | tar -x -C /tmp/love-v14-baseline
node scripts/audit-algorithm.mjs --baseline-dir /tmp/love-v14-baseline --baseline-ref e1018c4a2eb26b4dae29256f03a0b032a63a7bc1 --output /tmp/love-v15-audit.json

```

不传baseline-dir也可只检查当前算法。baseline-ref仅记录基线来源，读取的是baseline-dir中的实际文件；JSON另记录两版源码哈希。审计不改源码、不写题库、不调用网络；只有显式output路径才写结果文件。冻结输入摘要用于确认两轮模拟材料一致，不代表真人数据来源。
