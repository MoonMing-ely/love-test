更新：2026-10-06（Asia/Shanghai）；抽题方案修订：3，第六层接入状态同步。

抽题器、元数据、页面衔接及测试已实施；现有评分公式、原题题干和分值不变。新增四道已确认操题后，正式题库及本机浏览器全流程已验证；2026-10-06已接通第六层最终分与分层结果展示，本次修改未提交、未推送。

## 1. 范围和规则

数据流保持：Markdown 题库 → JSON → 抽题或恢复 → 答题 → 原评分链路。标准化继续使用本轮实际题目的 Raw / Capacity，不调整任何评分公式。

硬规则只维护一份，生成和恢复共用验证：

| 项目 | 要求 |
| --- | --- |
| 总数、配额 | 28 题；A12 / B6 / C6 / D4 |
| 最低覆盖 | 认需特稀各 ≥1；校证操合边止分自各 ≥2 |
| 资格 | 仅 valid；全轮题目 ID 唯一 |
| 语义 | 每个 semantic_group 最多 2 题 |

每维度按不同题目 ID 的集合计数，覆盖与独立证据合为同一机制。一题跨维度可以分别贡献一个来源；零分答案仍算回答了该维度的一道有效题。

软偏好：关键维度校证操边止分优先包含非 A 来源；优先新语义组；同组第二题优先不同题型。均不作为失败条件，也不为软偏好额外重抽。最终普通洗牌，连续题型和相邻语义优化不纳入 V1。

## 2. 数据与版本

每题只新增 dimensions、status、semantic_group，保留 id、stratum、type、prompt、options。stratum 表示 A/B/C/D，type 保持原文字类型；dimensions 使用现有英文评分 key。

元数据在 question-bank-source.md 的题目标题后维护，生成脚本解析为 JSON。valid 题需人工确认题干、归属、方向和选项；计分维度与 dimensions 一致，每个标注维度有非零可得分且选项能产生分值差异。不能只凭评分标签自动认定有效。review/disabled 不进入正式题池。

生成器检查结构、唯一 ID、元数据、评分合法性；正式题池容量由抽题器检查。这样审核期间可生成含 review 题的 JSON，但不足以满足正式约束时页面不得启动问卷。不得将暂时生成成功视为上线验收通过。

同步解除生成器、页面和测试中写死的 92 题及各类题库总量；保持 28 题配额、12 维和四个选项的检查。目前按已确认补题方案扩充至 96 题，原有 92 题保持不变。

题库结构版本升级为 4；评分结果版本不变。生成脚本使用 Node 内置 crypto 对固定字段顺序的 {dimensions, questions} 序列化内容计算 SHA-256，写为 bankRevision。无需人工递增，不增加依赖；相同内容重复构建修订号相同。抽题硬规则另有 selectionVersion，存档保存这两个标识。

## 3. 抽题流程

保留 sampleStratified(questions, 28, random) 入口、questions 和 allocation 返回字段；random 默认 Math.random。V1 只支持正式 28 题请求，其余题数报配置错误，不保留旧比例算法兜底。

```text
校验输入和配置 → 过滤 valid → 必要容量检查
最多尝试 100 次：
    重置本轮选择状态
    补齐校证操边止分 → 补齐合自 → 补齐认需特稀
    按题型剩余配额补满
    完整验证通过 → 洗牌并返回
    无候选或验证失败 → 丢弃本轮
耗尽 → QuestionPoolConstraintError
```

所有阶段共用加入条件：ID 未选、题型未满、语义组未满、属于 valid 题池。每次加入后更新全维度来源集合，循环必须加入一题或退出；每轮最多 28 题。

骨架阶段只考虑能补当前阶段缺口的题，依次比较：补缺维度数量 → 补非 A 来源数量 → 新语义组 → 同级随机。不能选择零贡献题继续循环，也不能把同一跨维度题当成一个维度的两份证据。

补齐配额时优先处理候选余量最少的题型：余量 = 当前可加入题数 − 该类还需题数；并列随机。该类内部优先新语义组，再优先不同题型的同组交叉验证，最后随机。余量仅是选择启发式，不能证明全局可行。

必要容量检查：valid ≥28、各类数量不少于配额、各维度来源不少于最低覆盖，以及 sum(min(2, 每组 valid 题数)) ≥28。未通过直接停止；通过也不等于已证明联合约束有解。不编写穷举求解器或复杂优化器。

有效题池只建一次，每轮选择状态独立；不修改输入题库或评分对象。成功返回 debug：selected_question_ids、type_counts、dimension_counts、dimension_question_ids、semantic_group_counts、attempt_count；第一轮成功记 1。页面不展示内部统计。

## 4. 失败与恢复

| 情况 | 处理 |
| --- | --- |
| 结构/配置错误、ID 重复、缺字段 | 立即停止，明确指出错误，不重抽 |
| 必要容量不足 | 抛约束错误，reason=pool_insufficient，指出不足项 |
| 本轮无候选或最终硬验证失败 | 丢弃本轮，计入最多 100 次 |
| 100 次耗尽 | 抛约束错误，reason=attempts_exhausted；不宣称题库必然无解 |
| 非预期程序异常 | 直接传播至页面错误处理，不把程序错误吞掉并重试 |
| 网络、JSON 加载失败 | 显示加载错误，禁用答题，保留旧存档 |
| 旧存档损坏、版本不符或恢复验证失败 | 重置内存中的本轮进度，正常生成；成功后覆盖旧存档并提示重新开始 |
| 存储读写失败 | 显示无法读取/保存进度，禁用答题；不重抽、不自动刷新 |

抽题器只负责数据、约束和生成错误；页面统一负责提示及停止交互。不能把所有错误都显示成“请用本地服务器打开”。题池不足显示无法生成；尝试耗尽可提示重新开始。不得回退旧算法、降低约束、返回少题结果或无上限自动重试。

恢复检查：selectionVersion、bankRevision 一致；28 个唯一 ID 可映射；统一硬规则通过；进度和答案数量一致；答案 ID 与题序对应；选项存在；分值快照与当前选项相同。通过后保留原题序、答案和进度，用原 fromAnswers 重建 Raw。没有存档不显示失效提示；失效提示需在首题渲染后仍可见。

首次生成只有在验证和存档写入成功后才允许答题。选择答案时先构造下一状态并尝试保存，成功后提交内存状态和进入下一题；写入失败停在当前题并禁用交互，避免内存进度领先存档。结果完成时先成功写入结果，再清理答题进度和跳转；结果保存失败保留已答状态，不跳转。清理失败停止并提示，不误报完成。用户明确重新开始时才主动清理旧结果。

JSON 解析失败表示存档内容损坏，可重建；访问 sessionStorage 本身抛错表示存储不可用，停止。上述处理覆盖启动、答题途中、完成三个阶段，不仅捕获启动错误。

## 5. 实施和验收

实施顺序：题库审核及操题确认 → 元数据/生成器 → 抽题器 → 页面恢复和错误处理 → 文档/首页说明 → 自动及页面验收。

涉及 data/question-bank-source.md、data/questions.json、scripts/build-question-bank.mjs、js/question-sampler.js、js/interactions/quiz.js、相关 tests 和 docs。需要提示区域时才小改 html/text.html；不修改核心算法文件，不新增服务，不提交或发布。

- 确认后的真实题库用 1000 个固定种子全部生成成功且满足硬规则；不能只统计成功的轮次。
- 小型题池验证跨维度独立计数、状态过滤、语义上限、各种容量不足、单轮失败后成功、100 次耗尽和程序异常不重试。
- 比较排序后的 ID 集合验证题组随机性；同种子可复现。不承诺均匀抽样，也不要求每道有效题都能入选。
- 检查重复构建修订号稳定；题目/分值/元数据变更修订号改变；输入对象未被修改。
- 页面验证刷新保持原题序与进度、重新开始、旧/损坏存档、错序答案、临时加载失败，以及启动/中途/完成时存储失败。失败不得推进、误跳转或无限重试。
- 运行现有评分链路测试，更新旧抽题比例断言和测试桩；真实页面完成一轮问卷确认数据衔接。

如果真实题库出现 100 次耗尽，验收不通过；先检查题池和选题策略，必要时单独评估简单回退，不靠扩大次数掩盖问题。1000 次通过是经验验证，不保证所有种子必成功，因此保留运行时上限和明确错误。
