# Love Test 卡片动效调研与初步方案

2026-11-11。范围：调研、解释和方案；未修改运行代码或部署。

## 判断

本轮目标是低响应延迟、可追踪的卡片运动和自然收尾。总时长可以适度增加。保留整张卡片抽出／归位、两张底卡联动和鼠标粉色悬停；点击仍用统一蓝色。此前把总时长当作主要优化指标，造成卡面消失与出现过急。

## 当前实现为何显得锋利

当前 `quiz.js` 在确认点击后等待 80ms，再把整张前卡移动 14px、透明度降到 0，退出用时 70ms；随后更新内容，下一卡用 110ms 进入，透明度由 0 变为 1。退出使用 `cubic-bezier(0.4, 0, 1, 1)`，进入使用 `cubic-bezier(0.16, 1, 0.3, 1)`。

这产生了三个不连续感：有色卡面被短暂拿走，底卡颜色暴露，再重新出现；退出最后几帧才迅速消失；进入的大部分变化集中在头几帧。入场曲线对位移和透明度一起生效，会把二者同时推得很急。

根据当前贝塞尔函数计算，在入场自身的 16.67ms 时，进度已达到约 65%；33.33ms 时约 88%；50ms 时约 96%。如果卡面从完全透明开始，这也是相应的不透明度进度。这里是数学计算，不是本轮真机逐帧测量；不能据此断言存在掉帧或浏览器渲染故障。

因此，“先快后慢”在代码里其实已经存在，只是起步太猛、时长太短，又与整卡显隐叠加了。

## 查到的设计原则和案例

### Apple：反馈要及时，运动要保持连续

Apple 把输入到画面更新的延迟与运动中途卡顿分开讨论：延迟很小但忽快忽慢的运动，也可能比稍长而稳定的延迟更刺眼。WWDC18 则强调工具应持续回应输入、允许中断，并保持空间关系。

对本项目的含义：按钮按下就回应；卡片不必在一百多毫秒内完成交接；不能为了等待动画而阻塞整个交互流程。

来源：[Understanding user interface responsiveness](https://developer.apple.com/documentation/xcode/understanding-user-interface-responsiveness)、[Designing Fluid Interfaces，WWDC18](https://developer.apple.com/videos/play/wwdc2018/803/)。

### Apple：弹簧不等于弹跳

WWDC23 解释了位置连续和速度连续的价值，展示了不回弹的弹簧；这类动画仍然能平顺地趋近终点。动画被重新指向另一个目标时，弹簧可以继承当前速度。Apple 还区分“视觉上已经基本完成”与“数学上彻底静止”，不建议用后者阻塞后续界面变化。

对本项目的含义：先试无回弹的自然收尾。问卷重复 28 次，明显抖动和反弹会增加负担。如果以后做真正的手指拖卡，速度继承比固定时长曲线更有价值。

来源：[Animate with springs，WWDC23](https://developer.apple.com/videos/play/wwdc2023/10158/)。

### Material：前后关系明确，也要避免淡出再淡入造成的闪烁

Material 的 shared axis（共享轴）适用于有前进、后退关系的页面，例如引导流程。其官方说明专门提到：默认 fade through 出现不希望的闪烁时，可以选择 fade 变体来改善连续性。Android 官方实现还区分空间运动与颜色／透明度效果；透明度不应像位置一样过冲。

对本项目的含义：前后卡可以同向接力；进入与退出不必串行等待；背景覆盖和文字切换要分开编排。不能把整张卡面的消失重新出现视作翻页的唯一表达方式。

来源：[Material motion system](https://m2.material.io/design/motion/the-motion-system.html)、[Material Components 官方 Motion 文档](https://github.com/material-components/material-components-android/blob/master/docs/theming/Motion.md)。

### Carbon：重复操作用克制的运动，大面积变化需要不同的节奏

Carbon 区分服务任务的 productive motion 与更醒目的 expressive motion，并把面积、距离纳入时长选择。它要求及时反馈，也要求运动之间有统一关系，不能把所有层都当作独立表演。

对本项目的含义：按钮与大题卡需要不同的时序；底卡只辅助表达厚度，不能抢在主卡前后各做一次动作。

来源：[Carbon Motion](https://www.carbondesignsystem.com/building-blocks/foundations/motion/overview)。

### DeepSeek Harness：区分官方项目与社区动效插件

已找到 [DeepSeek Harness 官方仓库](https://github.com/deepseek-ai/deepseek-harness)。具体可读到的相关动效案例是社区插件 [picklerick422/dsh-motion](https://github.com/picklerick422/dsh-motion)，不能把它的参数归为 DeepSeek 官方设计标准。

插件 README 描述了从触发位置展开的弹簧浮层、不同节奏的菜单和提示、连续气泡，以及图片的 FLIP 放大。其中对本项目最有用的是“同一个气泡移动并换内容”，避免上一层缩没再创建下一层。它也将弹簧响应时间与完整动画时长分开表达。

本轮仅把其 README 作为案例说明，未安装、运行插件，也未独立验证作者的帧率与兼容性结论。不照搬玻璃材质、液态变形或明显过冲。

## 几个概念怎样理解

**响应延迟（latency）**：从操作发生到第一处可见回应的时间。按钮立刻变蓝，就已经在回答“收到了”。

**总时长（duration）**：动作什么时候结束。一段 350ms 的动画也能及时回应，前提是它立即开始，主要信息尽早到位，剩下时间用于小幅收尾。

**缓动（easing）**：路程如何分配给每一刻。匀速像机械滑块；缓出会更早走完主要路程，然后减速。短促加速后再平缓减速，有助于避免起步突兀。它主要控制速度随时间的变化，不直接改变卡片走向。

**贝塞尔曲线（cubic Bézier）**：常见的时间到进度映射。CSS 的四个数描述控制点，并不是前四帧速度。相同曲线配不同总时长，实际速度会不同。

**阻尼弹簧（damped spring）**：目标像在拉着物体，阻尼逐步消耗运动。无回弹的弹簧也能带来柔和收尾；如果继承已有速度，操作中途改向不会先归零再重新启动。

**编排（choreography）**：决定谁先动、哪些动作同时发生、什么保持可见。当前问题需要改编排，单换一个曲线名不能彻底解决。

## 初步方案：立即确认、卡片连续接力、平缓收住

以下数值为项目起点，非官方推荐值或已验证的最终参数。

| 阶段 | 候选行为 |
|---|---|
| 按下 | 下一次可用绘制立即显示统一蓝色；不增加故意等待；松开才提交，滑动仍可取消 |
| 点击确认后 0–30ms | 答案提交与状态锁定后启动卡片运动，取消固定 80ms 静止停留；蓝色确认与卡片启动并行 |
| 旧卡约 140–160ms | 保留整卡抽出，向左约 14–18px、上移约 2px；采用短促起步后平滑减速，不用急剧加速后瞬间消失 |
| 新卡在旧卡启动后约 40–60ms 开始 | 从右侧约 10–14px 接入，约 260–300ms 归位；与旧卡有短暂重叠，避免等待旧卡完全透明才创建新卡 |
| 文字交接约 60–150ms | 旧题文字先退，新题文字再显；不能把两段正文长期重叠，也不复用整卡同一条显隐曲线 |
| 底卡与悬停 | 保留原底卡联动，弱于主卡并共享节拍；保留粉色悬停和 1px 上浮 |

整体动作候选约 320–360ms；新题争取在约 120–180ms 可读，尾部留给很小的归位变化。三者是不同指标，不把它们绑在同一个等待计时器上。时序重叠，表中时长不能相加。

**防闪优先处理表面连续性。** 动画期间用两张受控视觉卡层交接，或保留与前卡同色的承接表面，使同一区域不会先露出另一种底色再盖回；不是要求两张整卡都保持半透明。位移、卡面、正文分别安排，避免大面积亮度来回变化。长短题在同一个受控交接点更新布局，不能在归位尾段突然撑高。

**曲线起点。** 位移先比较 Material 标准曲线 `cubic-bezier(0.2, 0, 0, 1)` 与无回弹弹簧。前者有简短加速和较长减速阶段，后者适合需要中断、改向时保留速度。两者都需要和移动距离、时长一起判断。颜色、透明度使用单独的平滑曲线，避免过冲。若固定曲线已经满足点击翻页，不为“像 iOS”额外引入物理引擎。

**逻辑边界。** 展示副本只负责绘制，不复制按钮、计分或焦点；最多保留一张旧视觉卡，用完清理。答案仍只写一次，新题正式挂载前保持提交锁。新题可读且状态就绪后允许后续操作，不用等无意义的弹簧尾部；出现新操作时取消或接续旧的视觉收尾，不排队播放过期动作。

## 怎么判断下一版有效

先做独立可点击对照再接入答题流程。对照必须分别检查输入延迟、位移曲线、卡面连续性；避免同时改多种颜色和形状后难以判断原因。

记录按下到首帧反馈、点击到主卡开始运动、点击到新题可读、动画到稳定四个时间；拍摄正常速度和慢放。按钮应在下一次可用绘制反馈，但 60Hz／120Hz 的帧间隔不是对所有设备的硬保证。逐帧检查前卡区域是否突然变色、是否产生双重文字、长短题是否跳高。

同时验证手机和桌面、鼠标悬停、快速连续答题、回看改选、换题中打开 About，以及系统减少动态效果。减少动态效果时保留颜色确认，使用短内容溶解替代空间移动。最终手感由用户的正常速度体验确认，低端手机与 iPhone Safari 仍需真机检查。

本轮没有把方案写入运行代码；交互演示仅用于解释曲线差别，不是卡片成品预览。
