# Love-test 结果页文案调查报告

调查日期：2026-10-17。用途：为总分段、Stage、机制与维度描述的后续探索提供依据。

2026-10-18 更新：用户可见文字以[结果文案验收标准](../result-copy-acceptance.md)为准。本文旧样稿仅作研究参考，不是可直接上线的文案。

本文是研究与候选方案，不是已经批准的文案规范。没有修改题库、分值、算法、结果接口或页面。文中的中文示例均为原创探索稿，不是竞品原文，也尚未经过真人阅读验证。

## 1. 结论先行

**建议采用“预写完整段落 + 确定性选择 + 少量组合修正”的结果解释层。** 总分与 Stage 共用一套总览，机制解释主要受影响的位置，维度补充具体表现。自然感来自描述准确、情境具体、段落之间有关系，而不是模板数量或随机换词。

可以核查的证据有两类：开源 Big Five 文案库公开了按结果选择文本的接口；另一家 Big Five 产品的方法页明确声明基础报告使用预写内容，并把文案分段与经过验证的测量界限分开。两者说明这种实现路线可行，但不能据此推断所有测评都采用同样的内部系统。[开源文案库](https://github.com/Alheimsins/b5-result-text)、[方法说明](https://bigfivepersonalitytest.org/methodology)。

Love-test 最值得先解决的不是“写多少种”，而是这三个问题：

1. **一句话究竟由什么证据支持？** 总分不能替代维度，机制不能直接证明某种具体行为。
2. **几段话是否解释同一个人？** 心动强、判断稳、能止损，可以同时成立。
3. **语气是否超过了测量能力？** 当前结果不能判断某个伴侣正在欺骗用户，也不能预测被骗概率。

## 2. 调查范围与证据边界

本次检索人格测评、依恋测评、恋爱偏好测评与中文爱情测评，优先阅读官方说明、官方样例报告和公开代码。选取依据是与本项目的解释问题接近，而不是产品热度。

| 材料类型 | 可以确认 | 不能确认 |
| --- | --- | --- |
| 官方公开样例报告 | 已展示的章节、描述方式、主次组织 | 所有用户报告如何组合、是否实时生成 |
| 官方方法说明 | 产品对评分和文案机制的公开声明 | 声明是否全部被线上系统严格实现 |
| 开源仓库 | 该仓库公开的接口与实现 | 当前商业站点是否仍逐项使用该版本 |
| 中文商品介绍 | 宣称测量的维度与报告用途 | 付费报告全文、分段规则和生成逻辑 |

没有购买付费报告、创建测试账号、提交本项目的答案或用户个人资料；没有把搜索摘要中的第三方个人结果当作主要证据。此次调查不构成这些产品测量有效性的评定。

## 3. 同类产品如何解决

### 3.1 16Personalities：类型负责识别，连续倾向补充差异

**公开观察：** 官方解释将百分比用于说明一对相反倾向中的支持强度；接近中点时可能呈现两侧表现，并解释为何类型描述未必处处贴合。这里的百分比不是人群百分位。[官方说明](https://www.16personalities.com/articles/strength-of-individual-traits)。

**对 Love-test 的启发：** 可用简短等级帮助读者定位，再用具体倾向避免把等级写成完整人格。靠近边界的结果，描述不应突然从“判断稳健”跳到“完全失控”。

**不宜照搬：** Love-test 的十二维不是它的两极量表；不能复制其百分比含义或中点解释，也不能把 Stage 直接包装成人格类型。未取得其私有文案选择逻辑。

### 3.2 Truity Big Five：先解释维度，再解释个人落点

**公开观察：** 官方十四页样例按维度组织，包含维度定义、高低表现、个人分数与参考均值，以及个人解释段落。[官方样例，尤其第 1—3 页](https://www.truity.com/sites/default/files/fillpdf/sample_big_five_personality_test_report.pdf)。

**对 Love-test 的启发：** “这个维度测什么”和“你的答案呈现什么”应分开。否则用户会把每个人都能看到的定义，误认为专门针对自己的判断。

**不宜照搬：** 本项目没有对应常模，不能写“超过多数人”“低于平均”。样例中的细致人格外推也不应直接成为本项目文案依据。样例结构不能证明其后台一定怎样硬编码。

### 3.3 Truity 7 Love Styles：保留完整轮廓，按主次分配篇幅

**公开观察：** 样例区分接收爱与表达爱，先展示各项得分，再详述主要风格，补充次要风格；解释延伸到需要得到满足／未满足时的表现，以及沟通方式。[官方样例，尤其第 3—7 页](https://www.truity.com/sites/default/files/fillpdf/sample_7_love_styles_report.pdf)。

**对 Love-test 的启发：** 十二维不必在总览里平均占篇幅。可以保留全量详情，同时优先解释一两个有证据支持的关键位置；“表现—条件—可观察的提醒”比堆形容词更有内容。

**不宜照搬：** 最高分不自动意味着值得重点警示；所有维度都低时也必然存在第一名。必须同时考虑绝对强度。偏好测评的类型叙事也不能直接用来解释风险。

### 3.4 The Attachment Project：用多个连续维度容纳混合表现

**公开观察：** 官方说明以依恋焦虑与依恋回避两个连续维度呈现差异，并区分对不同关系对象的表现，而不是只给一个类型名称。[官方说明](https://www.attachmentproject.com/workplace/attachment-at-work/)。

**对 Love-test 的启发：** 看似矛盾的结果可能只是测量了不同位置。既容易被认可打动，又保有投入边界，应该被解释为一种组合。

**不宜照搬：** 当前 Love-test 没有分别测量对父母、伴侣等对象的完整结构，不能自行生成这类对象画像；也不能凭风险指数推断用户的依恋类型。

### 3.5 开源 b5-result-text：结果文案可以作为独立数据层

**公开观察：** 仓库将评分结果和语言传入文案模块；示例包含领域、子维度及 `neutral` 等结果标记，返回定义、个人解释与细项。入口文件分开调用模板加载与结果生成。[README](https://github.com/Alheimsins/b5-result-text)、[入口代码](https://github.com/Alheimsins/b5-result-text/blob/main/index.js)。

**对 Love-test 的启发：** 计算负责产生结构化结果，独立文案层负责选择已审阅文字，页面负责显示。这样调整措辞不必改算法。

**限制：** 本轮核查到 README 和入口；未成功取得内部 `generate-result.js` 正文，因此不声称掌握其全部分支、冲突处理或排序规则。

### 3.6 BigFivePersonalityTest.org：明确承认分段是编辑决策

**公开观察：** 方法页声明基础报告使用预写内容，分段为低于 40、40—60、高于 60；这些是组织文案的编辑区间，不是常模或临床界限。页面还披露部分可选工作报告使用可复用的 AI 辅助内容。[方法说明](https://bigfivepersonalitytest.org/methodology)。

**对 Love-test 的启发：** 把“为了写作而划段”与“经数据验证的差异”说清楚。后续可以在创作阶段借助工具起草、再人工审核并固化，用户查看结果时无需实时生成。

**限制：** 这是一家产品的自述，不代表行业共识，也不是它的算法已得到独立验证的证据。40／60 不适合作为本项目的默认维度阈值。

### 3.7 壹心理爱情依赖度评估：中文表达从可理解的关系问题切入

**公开观察：** 公开介绍列出情感依赖、孤独恐惧、恋人优先等五个方面，并说明报告用于理解依赖及关系匹配。[产品介绍](https://www.xinli001.com/ceshi/99897727)。

**对 Love-test 的启发：** 面向用户时，使用熟悉的关系经验作为入口，比直接呈现结构变量更容易理解。

**限制：** 未读取付费报告。不能据商品介绍推断它使用了何种分数段、组合模板或自然语言生成技术，也不据此评价报告质量。

### 3.8 这些材料共同支持到哪一步

已有直接依据支持：预写解释可用于结果报告；定义与个人解释可分离；完整轮廓与主次讲述可共存；连续差异与混合表现需要被保留。

**下面的内容是根据这些观察提出的 Love-test 方案，不是上述产品已经采用同一套方案的事实。** 本次没有发现足以证明“某种文案架构能显著提高用户准确感或信任”的对照证据。

## 4. 当前 Love-test 的真实边界

依据当前工作区代码与文档核查，不采用旧记忆中的题数或占位状态作为现状。

| 项目 | 当前实现 | 对文案的约束 |
| --- | --- | --- |
| 评分 | 六层计算，算法配置版本 1.4 | 文案读取结果，不暗中修正分数 |
| 完整答卷总分 | 当前可达范围 15—85；页面显示 `/100` | 不能写成概率、百分位或风险百分比 |
| Stage | 总分 `<30`、`<50`、`<70`、其余四段 | 本质是指数等级，不是关系发展的时间阶段 |
| Shape | A 整体稳定、F 单点突出、G 弥散中度、H 多路径高风险，或 null | null 不等于无风险；形状不能覆盖总分等级 |
| Path | 关系价值入口、判断盲区、行动失守、退出困难；选出 0—2 条 | 不保证每个人都有主路径或两条路径 |
| 十二维 | 风险倾向与保护能力并存 | 不能统一写成“分数越高越危险” |
| 当前结果适配 | `summary` 拼接 Stage、Shape 与 Path 标签 | 标签罗列尚未构成自然解释 |
| 当前页面 | 展示六层算法明细 | 面向用户的解释内容仍待设计 |
| 数据缺失 | 有 `insufficient_data`；R 未定义，一致性可为 null | 未测量／数据不足不能补写为正常、稳定或高能力 |

项目依据：[第六层](../../js/core-algorithm/sixth-layer-integration.js)、[算法配置](../../js/core-algorithm/algorithm-config.js)、[评分适配](../../js/scoring.js)、[结果页脚本](../../js/interactions/result.js)、[维度定义](../../data/questions.json)、[评分接口](../scoring-interface.md)、V1.4 校准说明（见 Git 提交 `eda4e2f` 的历史文件 `docs/algorithm-calibration-v1.4.md`）。

### 特别需要明确的两个区别

**Stage 与 Path 没有一一对应。** Stage 4 不等于“退出困难”，Stage 2 也不等于“关系价值入口”。前者来自总分，后者来自机制选择，不能用一个替另一个写结论。

**总分与维度不适合重复分段。** 当前 Stage 就是总分分段。首版宜让它们共用同一段总览，而不是先写四段分数解释，再另写四段 Stage 解释。若以后确实需要更细强度，再增加局部措辞，不新增第二套等级。

## 5. 分数段与 Stage 应怎样写

沿用现有分界，不在此次研究里改阈值。下表只是每段的写作任务，名称与最终文案仍待确定。

| Stage | 当前可达区间 | 总览应交代什么 | 不能仅凭此段断言 |
| --- | --- | --- | --- |
| 1 | 15 ≤ 分数 < 30 | 本轮整体风险信号较少，保留具体维度差异 | 不会被骗、每项能力都强、很难心动 |
| 2 | 30 ≤ 分数 < 50 | 风险信号有所呈现，重点要结合机制与细项判断 | 必然有单一弱点、只在特定情境失守 |
| 3 | 50 ≤ 分数 < 70 | 本轮整体信号更明显，指出实际支持的主要位置 | 已丧失判断、多项能力全面偏低 |
| 4 | 70 ≤ 分数 ≤ 85 | 本轮整体信号较强，需要具体说明哪些位置值得留意 | 已经受骗、伴侣有恶意、必须结束关系 |

可探索的四句基础总览：

- Stage 1：“这次作答中，整体风险信号较少。具体到哪些地方更容易被打动、哪些地方能稳住，还需要结合下面的表现来看。”
- Stage 2：“这次作答中，已经出现一些值得留意的风险信号。接下来更有帮助的是看看，它们主要落在哪些环节。”
- Stage 3：“这次作答呈现出较明显的风险信号。下面会进一步区分，这种影响主要体现在哪里。”
- Stage 4：“这次作答中，整体风险信号较强。比起只看分数，更值得关注的是，哪些反应让你较难保持自己的判断或行动。”

这些基础句刻意不承担完整画像，后面必须接机制或细项证据。它们目前仍偏说明性，后续可以在含义不变的前提下探索更温暖、更有个人感的表达。

对相邻边界的要求：29.9 与 30.0 可以改变等级，但不应据此生成两种相反的人格。初版不必再设复杂的“临界带”；先保证邻段含义连续。若以后加入临界提示，其宽度需要另行讨论，不能伪称置信区间。

## 6. 机制与十二维：怎样把术语翻成生活中的反应

### 6.1 先区分三种解释深度

| 层级 | 回答的问题 | 候选表达方向 |
| --- | --- | --- |
| 四机制 P1—P4 | 影响主要体现在哪个环节？ | 被关系吸引、作判断、落实边界、抽身离开 |
| E/J/B/H/F/M 等结构 | 多个细项如何形成一个整体？ | 需要时辅助解释，不要求全部做成用户栏目 |
| 十二维 | 哪种具体反应较突出？ | 对认可的反应、对行为证据的关注、能否执行边界等 |

首版建议把机制和十二维作为文案重点。第三层 B 同时汇总边界与止损，第四层又将两者分别使用；直接以 B 的均值写“行动能力”会掩盖重要差异。

P2 等机制可能由多个计算通道支持。仅凭 P2 高，不能自动写“你总在替对方找借口”：必须另外核对合理化相关证据。当前没有明确给出的心理成因，也不应由文案层自行补全。

### 6.2 十二维写作范围

下表是术语解释与写作提纲，不是已经选定的对外名称。“较高／较低”只指本项目量尺位置，不等于高于／低于人群平均；具体文案分段尚未确定。

| 维度 key / 当前名称 | 面向读者的问题 | 较高时可探索的行为语言 | 需要避免的外推 |
| --- | --- | --- | --- |
| recognition 人格认可敏感 | 对方认可我时，我会怎样理解这段关系？ | 对被理解、被肯定更有反应，较容易据此增加关系分量 | 缺爱、童年被忽视、自卑 |
| needed 被需要敏感 | 对方依赖我，会怎样影响我的投入？ | 更容易因“对方需要我”而想继续承担 | 天生讨好、控制欲强 |
| specialness 特殊性放大 | 我会不会把特别感看作关系依据？ | 更容易看重“我们之间不一样”的感觉 | 已被情感操纵、一定自恋 |
| scarcity 稀缺性判断 | “以后遇不到”会怎样影响我的取舍？ | 更容易因难得而提高关系的重要性 | 真的没有其他选择、客观择偶能力低 |
| calibration 关系校准 | 我的期待能否跟随关系现实调整？ | 更能依据实际关系状况调整预期 | 对方实际上不爱你、从不误判 |
| evidence 行为证据意识 | 我如何看待承诺与持续行动？ | 更关注对方是否持续做到，而不只听怎么说 | 能识破所有谎言、冷漠多疑 |
| manipulation 操纵识别 | 我能否留意互动中不合理的要求？ | 更容易注意施压、推卸责任等信号 | 对方就是操纵者、可判断具体人格障碍 |
| rationalization 现实回避/合理化 | 出现不舒服的事实时，我怎样解释？ | 较容易为问题寻找让关系继续成立的理由 | 明知故犯、没有自尊、故意自欺 |
| boundaries 投入边界 | 我的时间、金钱和精力是否有界限？ | 较能保留自己的投入范围，面对要求时有所取舍 | 所有情况下都能拒绝、付出少才正确 |
| stopLoss 止损能力 | 确认关系不合适后，我能否行动？ | 较能在需要停止时落实决定 | 不重感情、从不留恋、一定会分手 |
| differentiation 心理分化能力 | 对方的情绪与评价会怎样影响我？ | 较能保留自己的感受与立场 | 没有情绪、不需要亲密、回避型依恋 |
| selfCalibration 自我校准能力 | 我是否愿意检查和修正自己的判断？ | 较愿意回看依据，接受判断可能需要调整 | 绝对客观、拥有完整保护、作答一定真实 |

方向核查：前四项及合理化是风险倾向；关系校准、证据意识、操纵识别、边界、止损、心理分化、自我校准是保护能力。方向仍以现有题意与算法为准，不借这张表重新定义维度。

低风险倾向不自动等于一种积极人格：认可敏感低，不能直接写“自信独立”；保护能力较低也不能自动扩展为现实失败经历。

### 6.3 维度段落的推荐构成

每段优先写两到三句，覆盖：**触发情境 → 可能的反应 → 这项结果的含义或范围。** 这是编辑提纲，不要求把三个句子机械拼接。

例如，合理化信号较明显时可以探索：

> 当对方的表现让你不舒服时，你可能会先想，是不是对方最近压力太大，或自己误会了。有时，这会让原本需要认真看待的问题被暂时放下。可以留意的是：解释过后，对方的行为有没有实际变化。

例如，边界表现处在中间区间时可以探索：

> 在投入这件事上，你的回答既包含保留，也包含让步。它提示我们需要进一步看清，哪些要求你能拒绝，哪些要求会让你犹豫。

第二段没有直接编造“你对所有人都守界限，唯独对喜欢的人会失守”。**维度中间值只表明量尺落在中间，不足以单独证明具体的情境切换。** 若要写出这种差异，需要多维或作答证据支持。

## 7. 如何硬编码得自然

### 7.1 采用分段组合，不做逐词造句

| 路线 | 优点 | 代价 | 当前判断 |
| --- | --- | --- | --- |
| 每个分数一篇全文 | 读取简单 | 同分不同画像被压平，维护量大 | 不优先 |
| 十二维全文组合穷举 | 可为每种组合精写 | 三档即有 3¹² = 531,441 种组合 | 不适合 |
| 随机短句拼接 | 看起来变化多 | 指代、语气和含义容易断裂，同结果不稳定 | 不优先 |
| 完整模块 + 少量组合段 | 可审核、可追溯、能保留关键差异 | 需要处理模块之间的冲突和重复 | 建议首版使用 |
| 每次实时调用模型 | 表达灵活 | 成本、等待、隐私及输出一致性增加工作量 | 当前无须引入 |

预写不等于每段都泛化。应当把变化放在**选择哪些事实、解释哪些关系**上，而不是把“容易”随机替换成“往往”。

### 7.2 建议的解释顺序

```text
现有算法结果
  → 有效性与版本检查
  → 总分 / Stage 总览
  → 已入选的主要机制（允许没有）
  → 必要的组合解释或限定
  → 相关维度详情与提醒
  → 文案选择记录
  → 页面渲染
```

总览讲整体程度，机制讲位置，维度讲反应，提醒讲可观察的动作。同一事实不要在四处各重复一次。

若已有组合段覆盖“心动强但行动稳”，应替换相关的独立泛化段，或删去其中重复的句子；不要在原来两段后面再追加一段自我纠正。

### 7.3 最值得先写的组合，不是所有组合

| 组合条件（须后续精确定义） | 为什么值得写 | 探索句 |
| --- | --- | --- |
| 关系价值信号强 + 边界与止损有支撑 | 避免把容易心动等同于容易失守 | “你可能很容易被一段关系打动，但在实际投入和是否继续上，仍会给自己留出判断的空间。” |
| 判断相关能力有支撑 + 边界偏弱 | 区分看见问题与采取行动 | “你未必看不出哪里不对，更难的可能是把自己的判断变成一次明确的拒绝。” |
| 边界有支撑 + 止损偏弱 | 区分日常设限与结束关系 | “你能对一些要求说不，但当问题变成‘要不要离开’，决定可能会难得多。” |
| 合理化信号强 + 自我校准有支撑 | 保留倾向与修正能力共存 | “你可能会先替对方寻找解释，也保留着回过头重新检查这些解释的能力。” |
| 多条机制接近且有足够信号 | 避免强行定成唯一类型 | “这次结果没有集中在单一环节，几个位置都值得一起看。” |

这些句子只有在两侧证据同时满足时才可使用。P 值和维度分数不是同一东西，不能为了套句子而改变算法定义。

### 7.4 每条文本需要带什么信息

后续可把文案存为独立 JS 数据或 JSON；首次实现不必引入数据库、后台编辑器或新的评分层。每个条目至少记录：

- 稳定 ID、文案版本、适用算法版本，以及探索稿／已审阅状态。
- 所需字段与适用条件；依赖的是维度、机制还是总分。
- 完整正文，以及该段允许表达的结论。
- 缺失数据时的处理、冲突段落、重复主题和优先级。
- 可核查的选择理由，供开发与审稿使用。

例如记录“选中 `combo.boundary-stoploss-gap`，因为边界与止损满足指定组合”，比只保存一句最终文本更方便排查。该组合 ID 为候选命名，当前未实现。

同一份结果、同一文案版本应给出同样的描述；不需要为了新鲜感随机轮换。将来若保存文案版本或快照，需要结合现有存储兼容策略另行设计。

### 7.5 首版文案规模估算

若十二维先各设低／中／高三档：4 段 Stage 总览 + 36 段维度解释 + 4 段主机制解释 + 6—10 段关键组合 + 4—6 段状态提示，约 **54—60 个内容条目**。这是编辑工作量估算，不是最终架构要求，也不表示本轮已定义各维度阈值。

Shape 首版可以仅用于决定“集中讲一处还是多处”，无需强行增加独立栏目。建议与主体解释共同审阅提醒语，避免为同一条结论再写一套互不关联的建议库。

## 8. 自然表达的判据与反例

| 常见问题 | 不宜使用 | 可探索的改写方向 |
| --- | --- | --- |
| 把指标换个说法 | “你的关系价值放大机制较高” | 写清楚何种认可或特别感会增加关系分量 |
| 给人贴标签 | “你是典型恋爱脑” | 描述这次答案中出现的具体反应 |
| 伪具体 | “凌晨两点，你总忍不住翻聊天记录” | 不添加题目没有测量的习惯、时间和经历 |
| 泛化讨好 | “你很善良，只是太重感情” | 区分愿意付出与是否能拒绝不合理要求 |
| 两头都说 | “你既理性又感性，有时坚定有时犹豫” | 明确在哪个环节保有判断，在哪个环节较难行动 |
| 高低二分 | “边界高，所以你不会受伤” | 说明本项表现与适用范围，保留其他风险 |
| 概率包装 | “你有 73% 的概率被骗” | 使用指数与本轮作答信号，避免概率推断 |
| 虚构原因 | “你这样是因为童年缺乏安全感” | 未测量的成因不进入结果 |
| 每句都含糊 | “你或许可能在一定程度上……” | 在段首交代依据来自本轮作答，正文使用清楚而有限的判断 |

“可能”并不能修复没有依据的判断。自然的重点是读者能理解、能核对、能指出哪里不适用，而不只是觉得被安慰。

## 9. 进入实现前怎样验收

先通过[新版语言验收](../result-copy-acceptance.md)，再检查以下内容与边界。不得仅凭算法正确就判定文案合格。

### 9.1 必须覆盖的结果情形

1. **同分不同机制：** 相近总分分别来自判断偏移和退出困难，总览强度相近，核心解释应不同。
2. **容易心动但行为稳健：** 不出现全面失控或“不会拒绝”的断言。
3. **判断较强但边界偏弱：** 不写成看不出问题。
4. **边界较强但难退出：** 两项解释可以同时成立。
5. **保护值较高但总分仍高：** 不写成全局安全，也不假称保护完全消除了风险。
6. **全部信号较低：** 不因为必须选“最高维”而制造显著弱点。
7. **路径为空、双路径、Shape 为 null：** 都有自然的结果，不使用 null 证明稳定。
8. **维度中间值：** 不无依据地宣称人群平均、真实内心矛盾或某种特定关系模式。
9. **分段与显示边界：** 检查 29.99／30、49.99／50、69.99／70；若数字四舍五入显示为 30 而 Stage 仍为 1，须在数字展示方案中解决，不能偷偷改评分规则。
10. **数据不足、旧版、无结果：** 不输出个人画像；null 不当低分。

实现后可以复用现有全链路测试产生结构化结果，再检查文案选择覆盖、方向、冲突与确定性。纯文案研究阶段无须跑算法回归，也不以测试通过代替文字阅读。

### 9.2 真人阅读要检验什么

建议先用现有模拟画像做内部审稿，再邀请少量自愿读者做探索性阅读，例如 5—8 人；这只是发现表达问题的试读，不是测量有效性验证。

先请读者在不看算法细节的情况下说出：结果最想告诉自己什么、哪句话对应得上经历、哪句话有误、是否存在互相矛盾的段落。不要只问“准不准”或“喜不喜欢”。

可以给出一份与其结果匹配的描述及一份机制不同的描述，请读者说明差异。若两份都被认为完全适用，应检查是不是措辞过于普遍；这种试读仍不能单独证明效度。

## 10. 后续探索的建议顺序

1. **先选八个代表画像，手写完整报告。** 可从已有模拟画像出发，覆盖整体稳定、易心动但行为稳健、判断偏移、行动边界弱、退出困难和多机制并存；说明模拟不是真人验证。
2. **比较文风。** 对同一画像尝试更直接、更温暖、稍有文学感的表达，核对含义是否一致，再由用户选择方向。
3. **抽取可复用模块。** 从自然的全文中归纳 Stage、机制、维度与组合段，避免先搭碎句库再硬凑文章。
4. **讨论十二维的文案分段。** 结合量尺含义、题目覆盖与已知波动决定；明确哪些只是编辑区间，不擅自借用竞品 40／60 或按三等分切段。
5. **文案与规则确认后再接入。** 优先独立解释层，保持六层算法职责；完成边界、冲突与真实页面阅读检查。

下一轮最有价值的具体产物是：**同一文风下八份完整结果样稿，以及每个判断所对应的字段与证据。** 先确认它们像是在解释八种有差异的结果，再决定需要多少模板。
