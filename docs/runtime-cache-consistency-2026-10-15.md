# Firefox预览完成答题时报错：脚本版本混用

## 故障证据

用户在 `http://127.0.0.1:8000/html/text.html` 完成最后一题后，页面显示「测试暂时无法继续，请重新打开页面」。控制台显示 `RangeError: C 必须是 0～1 的数字或 null。`，栈指向 `sixth-layer-integration.js:51`。

服务器返回的HTML、题库及JS均与当前磁盘内容一致。此前独立Firefox配置的完整答题测试通过，但该测试未覆盖已有浏览器缓存。

截图第51行对应旧版第六层的输入校验；当前第六层相同校验在第69行。因此用户当次执行了旧版第六层，而非服务器当前提供的完整新版本。

旧AlgorithmConfig缺少新版P2所需的P2_JUDGMENT_WEIGHT、P2_WEAK_JUDGMENT_WEIGHT与P2_AVOIDANCE_WEIGHT。与新版第五层混用时，乘法和Math.max会得到NaN，随后第六层以路径代号C报错。这不是正常风险分数超过上限。截图未直接揭示用户缓存了哪份上游文件；旧配置与新计算模块混用是已明确复现同一错误的一种组合。

## 修正

答题页的抽题器、第一至第六层模块、配置、评分适配器和答题控制器，以及结果页的算法配置和展示脚本，统一使用带同一发布版本参数的URL：

`?v=20261015-runtime-v14-v4-1`

浏览器不会把旧的无版本脚本缓存用于新的版本化URL。未修改评分算式、权重、保护机制、输入数值校验和抽题规则，也未把NaN强制转换成0。

以后修改这组脚本时，答题及结果页相关资源的发布版本应一起更新，避免继续复用旧发布URL。部署或预览时须重新加载HTML；已经打开的旧页面不会自动更换其正在执行的脚本。

## 验证

1. Node隔离执行旧配置＋新版第四/第五层＋旧第六层：P2为NaN，第六层在第51行抛出与用户相同的RangeError。
2. 临时本机HTTP服务将旧配置、旧第六层以可缓存的无版本URL提供，真实Firefox执行28次实际选答：复现相同错误，未完成状态保留28条答案。
3. 同一浏览器配置、同一源、同一会话改用新版HTML和版本化脚本，重新加载后成功读取原答卷并进入结果页，28条答案完整，总分约73.2173。此恢复示例的题库修订号与抽题规则版本一致；不承诺恢复其他已失效版本的答卷。
4. 新增runtime-assets测试，检查答题与结果页相关资源有版本参数且发布版本一致。15个Node测试文件全部通过。

本轮另外已按用户原话将C25-D改为「莫名其妙，滚一边去。」，止损仍为+3，并重新生成题库。该文案修改改变bankRevision；旧修订号的未完成问卷仍按原守卫失效，本次未放宽恢复条件。
