# 结果文案实现方案

更新：2026-10-20。状态：文字第一版与独立引用模块已完成；结果页接入尚未执行。

## 1. 本版范围

采用总—分—总：分数和档位 → 受骗倾向总述 → 多维度特点 → 温暖结语。

中间正文在上一版基础上压缩约 20%，七份实际减少约 18%—19%。通常约 130—190 个汉字，覆盖四至六个有依据的维度；无突出特点时可以更短。完整句、自然中文语序和各句不同的含义优先。结语保留已确认的风格，不随正文压缩。

类型名继续待定，运行结果 `type` 为 null。本轮不改变题库、抽题、分值、六层算法、存储格式或页面布局。

## 2. 实际文件安排

| 文件 | 职责 |
| --- | --- |
| `data/result-copy.json` | 唯一文字源、映射、选择条件与样例维度 |
| `scripts/build-result-copy.mjs` | 校验并生成浏览器目录，同步可阅读样稿 |
| `js/result-copy/catalog.js` | 自动生成并深度冻结的静态目录 |
| `js/result-copy/selector.js` | 校验输入、选择文字，返回纯数据 |
| `tests/result-copy.test.mjs` | 样稿、边界、异常、真实答卷与抽题回放 |
| `docs/result-copy-usage.md` | 当前接口、字段映射、维护和页面引用示例 |
| `docs/result-copy-v1.md` | 具体文案、完整样稿、未采用素材及审稿依据 |

目录与选择器留在 `core-algorithm/` 之外。评分只管评分，文字只解释已经产生的结果。

## 3. 调用与选择

入口：`ResultCopy.build({ outcome, normalizedDimensions, layer6Integration })`。

不读存储、不访问 DOM 或网络、不修改输入、不重新评分。页面原有完整答卷校验仍然保留。详细输入输出以[引用机制](result-copy-usage.md)为准。

1. 核对记录、算法版本、分数、Stage、Path 与十二维值。
2. 根据原 Stage 选择程度开头，不从 Stage 推断性格。
3. 优先检查六份完整个性段落，每项必要维度条件都成立才引用。没有突出特点时另用中性样稿。
4. 不满足完整段落条件时，从十九条单项选择最多六项；同一主题最多两项，风险与保护均有依据时各保留一项。
5. 依现有 Path 顺序、维度偏离中点的幅度、目录顺序选取，再按固定阅读顺序组织段落。
6. 结语回应已选特点，作为期待表达，不作为性格证据。

高侧门槛 0.65、低侧门槛 0.35 是编辑参数，未改变评分规则，也没有经真人研究验证。中间值不强行编造倾向。能力项保持原有高值含义；前四项与合理化的低侧不自动写成优点。

同一输入与同一文案版本返回一致的文字。文案版本为 `1.0`，当前只支持算法 `1.6`。无随机句库、无在线生成、无可执行条件字符串。

## 4. 异常与展示边界

| 情况 | 返回 |
| --- | --- |
| 有有效特点 | `ready`，完整段落或单项组合 |
| 十二维有效但没有突出项 | `fallback`，中性解释与通用祝愿 |
| 任一维度明确为 null | `fallback`，保留已校验分数，说明信息不足，不编造特点 |
| 缺字段、坏数值、版本不支持、分数档位矛盾 | `unavailable`，返回对应提示 |
| 整体测量不足 | `unavailable`，不生成个人解释 |

分数按两位小数截断，原值不变。29.999／30、49.999／50、69.999／70 两侧显示不得因四舍五入而越档。模块不承担页面的所有历史记录验证。

## 5. 页面接入留到下一阶段

接入点是 `js/interactions/result.js` 现有校验之后。加载顺序：算法配置 → 文案目录 → 选择器 → 结果交互。用 `textContent` 渲染，`paragraphs` 和 `sentences` 不重复输出；类型为 null 时不显示类型行。

页面接入需要同时核查：分数与说明是否重复、技术明细如何保留、滚动区观察节点、导航、重测、刷新、分享截图和脚本缓存版本。布局与真实浏览器读感单独验收。本轮未修改这些页面行为。
